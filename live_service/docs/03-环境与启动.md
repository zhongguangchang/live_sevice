# 生活服务网 · 环境要求与启动手册

这份文档记录的是实际踩坑之后验证过的配置，不是照抄教程的默认值。
换一台机器部署时照着做可以避开全部已知的坑。

---

## 一、JDK：必须是 17

**不能用 JDK 21 / 24。** 原因有两层：

1. 项目用的 Spring Boot 2.7.3（Spring Framework 5.3.22）官方只支持到 JDK 17
2. Lombok 1.18.20 只支持到 JDK 16，在 JDK 17 及以上编译会报：

```
java.lang.NoSuchFieldError: Class com.sun.tools.javac.tree.JCTree$JCImport
    does not have member field 'com.sun.tools.javac.tree.JCTree qualid'
```

本项目已经把 Lombok 升到 **1.18.22**（支持 JDK 17），但如果你非要用
JDK 21/24，还需要继续升到 1.18.30+，而且 Spring Boot 2.7.3 本身
在新 JDK 上能否正常运行也没有保证。

### 本机配置

| 项 | 值 |
|---|---|
| JDK 路径 | `D:\jdk17\jdk-17.0.2` |
| `JAVA_HOME`（用户级） | `D:\jdk17\jdk-17.0.2` |
| IDEA Project SDK | `17`（IDEA 里的 JDK 名就叫 `17`） |
| IDEA Language level | `JDK_17` |

设置方式（已执行过，换机器时重做）：

```
setx JAVA_HOME "D:\jdk17\jdk-17.0.2"
```

设置后**要新开终端才生效**（环境变量只对之后启动的进程有效）。

如果 IDEA 里跑 Maven 报 JDK 版本错，去
`Settings → Build, Execution, Deployment → Build Tools → Maven → Runner`，
把 **JRE** 设成 `Use Project JDK`。

MySQL 装在本机 Windows，Redis 和 RabbitMQ 装在 Linux 虚拟机上。

| 组件 | 地址 | 账号 / 密码 | 说明 |
|---|---|---|---|
| MySQL | `127.0.0.1:3306` | `root` / `123456` | 库名 `life_service` |
| Redis | `192.168.229.129:6379` | 密码 `123456` | database `10` |
| RabbitMQ | `192.168.229.129:5672` | `admin` / `123456` | vhost `/` |
| RabbitMQ 管理台 | `http://192.168.229.129:15672` | `admin` / `123456` | 浏览器直接开 |

### 验证连通性

在 PowerShell 里（注意 `Test-NetConnection` 是 PowerShell 命令，cmd 里没有）：

```powershell
Test-NetConnection 192.168.229.129 -Port 6379
Test-NetConnection 192.168.229.129 -Port 5672
```

`TcpTestSucceeded : True` 就是通。

Redis 凭据验证：

```bash
redis-cli -h 192.168.229.129 -a 123456 ping    # 应返回 PONG
```

RabbitMQ 直接在浏览器打开管理台，能登录进去就说明网络、账号、vhost 全对。

## 三、端口：后端用 8081，不用 8080

**本机的 8080 端口被 Windows 系统保留了，任何程序都绑不上。**

```
netsh int ipv4 show excludedportrange protocol=tcp

Start Port    End Port
        80          80
      8080        8080
     50000       50059     *
```

`80` 和 `8080` 都在系统排除范围内。这是 `hns`（主机网络服务，通常来自
Hyper-V / Docker / WSL）预留的，不是被某个程序占用，所以杀掉进程没用。

因此后端端口改成了 **8081**，前端 `.env.development` 里的
`VUE_APP_URL` 和 `VUE_APP_SOCKET_URL` 也要同步改成 8081，
否则管理端能登录但订单推送会静默断开。

## 四、启动步骤

### 1. 确认中间件

Redis 和 RabbitMQ 在虚拟机上，确保虚拟机已启动、网络可达。

### 2. 初始化数据库（首次）

```
mysql -h127.0.0.1 -uroot -p123456 --default-character-set=utf8mb4 < db/life_service.sql
```

脚本是幂等的（全部用 `CREATE ... IF NOT EXISTS`），可以重复执行。

### 3. 启动后端

**不要直接在根目录跑 `mvn spring-boot:run`。**
根目录 `live_service` 是聚合模块（`<packaging>pom</packaging>`），
它没有代码也没有主类，会报：

```
Unable to find a suitable main class, please add a 'mainClass' property
```

正确的方式是进到 `sky-server` 子模块再跑：

```powershell
cd D:\campus\live_service
mvn install -DskipTests      # 改了 sky-common / sky-pojo 之后必须先跑这步
cd sky-server
mvn spring-boot:run
```

或者留在根目录，用 `-pl` 指定模块：

```powershell
cd D:\campus\live_service
mvn install -DskipTests
mvn -pl sky-server spring-boot:run
```

> 为什么必须先 `install`：`sky-server` 依赖 `sky-common` 和 `sky-pojo`，
> 单独构建 `sky-server` 时这两个模块是从本地 Maven 仓库取的 jar。
> 改了实体类或常量类却没重新 install，就会报「找不到符号」。
>
> 在 IDEA 里直接运行主类没有这个问题 —— IDEA 会从源码构建全部模块。

启动成功的标志：

```
Tomcat started on port(s): 8081 (http)
Started SkyApplication in 3.7 seconds
RabbitMQ 交换机 / 队列 / 绑定声明完成
```

接口文档：<http://localhost:8081/doc.html>

### 4. 启动管理端

```powershell
# PowerShell
cd "D:\campus\前端源码\生活服务网前端源码\project-sky-admin-vue-ts"
npm install
npm run serve
```

```cmd
:: cmd（命令提示符）
cd /d "D:\campus\前端源码\生活服务网前端源码\project-sky-admin-vue-ts"
npm install
npm run serve
```

默认端口 8888，浏览器会自动打开，用 admin / 123456 登录。

#### 这个前端是 vue-cli 3 时代的老项目，在 Node 17 以上有三个坑

都已经在前面处理好了，这里记录原因，换机器时如果又遇到可以对照：

**一、peer 依赖冲突** —— npm 7+ 默认严格校验 peerDependencies，
而 vue-cli 3 的各插件声明的 eslint / webpack 版本互相矛盾，直接 install 会报：

```
Could not resolve dependency: peer eslint@"^5.0.0" from eslint-plugin-vue@5.2.3
```

解法是项目根目录放一个 `.npmrc` 写 `legacy-peer-deps=true`，
让 npm 退回 6.x 的宽松行为。也可临时用 `npm install --legacy-peer-deps`。

**二、fibers 装不上** —— 它是原生模块，只支持到 Node 16，
在 Node 17+ 上 node-gyp 编译必然失败，会中断整个 install。
它只被 sass-loader 用来做异步编译，属于可选优化，已从 package.json 移除。

**三、md4 哈希被移除** —— webpack 4 用了 OpenSSL 里已被删掉的 md4 算法，
Node 17+ 下启动 dev server 会报 `ERR_OSSL_EVP_UNSUPPORTED`。
package.json 里的 serve / build 脚本已经改成：

```
node --openssl-legacy-provider node_modules/@vue/cli-service/bin/vue-cli-service.js serve
```

这样不需要额外装 cross-env 就能跨平台生效。

> ⚠️ 如果你把 Node 降到 16（老项目兼容性最好），
> 要把脚本里的 `--openssl-legacy-provider` 去掉 —— Node 16 不认识这个参数。

> 另外移除了 `@vue/cli-plugin-e2e-cypress`：它的 Cypress 二进制包要从国外
> CDN 下载，国内经常装不上；毕业设计用不到端到端测试。

## 四点五、命令行的两种终端（重要）

Windows 上有两个终端，命令**不通用**，用错会报「不是内部或外部命令」。

| 操作 | cmd（命令提示符） | PowerShell |
|---|---|---|
| 切换盘符目录 | `cd /d "D:\path"` | `cd "D:\path"` |
| 删除目录（递归强制） | `rmdir /s /q 目录名` | `Remove-Item -Recurse -Force 目录名` |
| 设置临时环境变量 | `set VAR=值` | `$env:VAR="值"` |
| 测试端口连通性 | 无内置命令，需 `powershell -c "Test-NetConnection ..."` | `Test-NetConnection 主机 -Port 端口` |

**cmd 里换盘符必须加 `/d`**，否则 `cd D:\xxx` 不会真的切过去，
提示符看起来没变就是这么回事。

本文档后面给出的命令默认是 PowerShell 写法，用 cmd 的话对照上表转换。

## 五、已知坑位速查

| 现象 | 原因 | 解决 |
|---|---|---|
| `JCTree$JCImport ... 'qualid'` | Lombok 版本不支持当前 JDK | 用 JDK 17 |
| `Web server failed to start. Port 8080 was already in use` | 8080 被系统保留，非程序占用 | 换 8081 |
| 启动报 `documentationPluginsBootstrapper` NPE | Springfox 3.0.0 不支持 `PathPatternParser` | 已修：`spring.mvc.pathmatch.matching-strategy: ant_path_matcher` + 排除 actuator |
| `spring.mvc.*` 配置不生效 | 继承了 `WebMvcConfigurationSupport`，导致 MVC 自动配置退避 | 已修：改实现 `WebMvcConfigurer` |
| RabbitMQ 管理台里看不到队列 | `RabbitAdmin` 要等第一次连接才声明，没有消费者就不连 | 已修：启动时主动 `amqpAdmin.initialize()` |
| `Table 'life_service.orders' doesn't exist` | 旧代码的定时任务在查老项目的表 | 已修：注释掉 `OrderTask` 里的 `@Scheduled`，待重写 |

## 六、校验工具

项目里有两个开发期校验工具，改完 Mapper 后建议跑一下。

**Mapper 与 XML 是否一一对应**（不需要启动 Spring、不需要数据库）：

```
java -cp <依赖classpath> com.sky.MapperXmlCheck
```

源码见 `sky-server/src/test/java/com/sky/MapperXmlCheck.java`，
它会把每个 Mapper XML 交给 MyBatis 真正解析一遍，
能查出类型别名写错、resultType 类不存在这类只有运行时才暴露的问题。
